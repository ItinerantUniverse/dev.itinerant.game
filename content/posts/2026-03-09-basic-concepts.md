For the longest time I didn't really see Itinerant as being a fully-immersive survival game.

I thought a lot about the fact it was an open world sandbox, but I was reluctant to call it any of those things because there are absolutely _tons_ of those ideas floating around and it just felt a bit like 'oh, you're writing an open world sci fi survival game? Like there aren't enough of those?'.

I was writing a version of this game before No Man's Sky appeared, and then when No Man's Sky came out, I literally gave up on what I was doing because I figured it had already been done.

It was only several years later that i actually _played_ No Man's Sky that I realised it wasn't really the same thing as what I had in mind. I've been finding it difficult to explain in actual words what it is I'm trying to make, it's just I knew it wasn't No Man's Sky and that I should've just carried on with what I was doing.

So I think I do now have some core concepts that define Itinerant, and I'm going to split them down into a few different categories. The first category is - what is it like to play?

- It is as immersive as I can make it. I initially wanted absolutely no overlays, HUDs or anything like that. Everything you see in the game is rendered in the 3D virtual world environment, and that should be it. I have _slightly_ modified this by making an assumption that you're wearing some sort of space helmet with a HUD built in, which means certain text is being projected in front of your eyes - hence it's now totally ok for some sort of *basic* HUD to exist. I just don't want any 2D overlays or things that break the feeling that you're immersed in the Itinerant world.
- No loading screens or 'please wait' stuff like that. If there _has_ to be a loading time, then there needs to be some sort of in-game explanation for it.
- Everything should work properly. If there is a computer in the game, then you can plug it in and use it, and it is literally a working, in-game computer, not just like a thing where you can cilck four different options and then it gives you some information.
- Similarly, you should be able to build structures and vehicles and have it feel realistic without ever breaking the fourth wall. In Starfield for example, you can build you own spaceships but you have to go into this editor mode to do it. In Itinerant, I just figure you should pick up parts and place them, like Minecraft but in a more organic and less voxel-y way.
- Procedural generation of elements should always be secondary to simulated solutions. For example, if there's weather on a planet, it exists because we're using an actual simulation of weather based on things like the amount of heat/sunlight hitting the planet, the density and composition of the atmosphere, how elevation and water bodies affect the weather, etc.
- The world is a multiplayer environment where everything is persistent. If you dig a hole in the ground, build a structure, or blow up a vehicle, whatever it is you do, it's going to stay that way and everyone else in the game will see it. The only caveat to this is if I get far enough into building some RPG elements, in which case they may have to take some sort of linear progression - a bit like the difference between playing Read Dead Redemption 2 and Red Dead Online.
- There has to be some sort of battle/combat element to Itinerant, but I don't yet know how well to define the realism of this.
- I want you to have this entire vast world to explore and build within, but at the same time you should be able to retreat back into some sort of much smaller 'base' that you still have plenty to do and acts as your home. It should feel a bit like being outside on a really cold day and finally getting home to bed and wrapping up warm. Often I've tried playing games with base-building in them, but once you've completed a build, it doesn't become this thing you want to keep coming back to - it doesn't feel like home. Your bases in Itinerant should feel like home.
- The weather and the environment can be as much of a threat to you as any enemies that might exist.
